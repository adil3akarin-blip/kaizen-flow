## 1. Что за продукт

**KaizenFlow: Power & Focus** — PWA, помогающее освободить голову от тревог, выстроить дела в равномерный поток и двигаться к целям без насилия над силой воли.

Главная идея — **синергия двух систем**:
- **Кайдзен** организует дела в непрерывный поток, защищая от хаоса.
- **Power Management** поставляет для этого потока стабильно высокий уровень энергии.

Полное продуктовое видение — в [context/IDEA.md](context/IDEA.md). Дорожная карта реализации — в [docs/superpowers/specs/2026-06-07-kaizenflow-roadmap.md](docs/superpowers/specs/2026-06-07-kaizenflow-roadmap.md).

Продукт состоит из 4 модулей:
1. **«Чистая голова»** — моментальная выгрузка мыслей на холст (частично реализован).
2. **«Фильтрация и Осознанность»** — отбор задач через фильтры «Хочу/Должен», «Миссия и Цели».
3. **«Канбан-поток»** — организация дел в поток с WIP-лимитами и pull-системой.
4. **«Хаб Power Management»** — мониторинг и балансировка энергии.

## 4. Конвенции кода

- **Только функциональные компоненты** с хуками. Дефолтный экспорт компонента из его файла.
- **Селекторы Zustand по одному значению за раз:**
  ```js
  const cards = useCardsStore((s) => s.cards)
  const addCard = useCardsStore((s) => s.addCard)
  ```
  Не доставай весь стор одним вызовом — это вызывает лишние ре-рендеры.
- **Чистые функции — в `lib/`**, без побочных эффектов и без обращений к React. См. [src/lib/cardUtils.js](src/lib/cardUtils.js) как образец.
- **Условные классы — через `clsx`**, не через ручную конкатенацию строк.
- **Именование:** компоненты — `PascalCase`, хуки/функции/переменные — `camelCase`, файлы компонентов — `PascalCase.jsx`, файлы утилит/стора — `camelCase.js`.
- **Комментарии по умолчанию не пишем.** Добавляй комментарий только когда «почему» неочевидно (скрытый инвариант, обход бага). Не описывай «что» делает код.
- **Без преждевременных абстракций.** Три похожие строки лучше преждевременного хелпера. Не закладывайся на гипотетические будущие требования.

Цвета стикеров — в `STICKY_COLORS` ([src/lib/cardUtils.js](src/lib/cardUtils.js)).

**Принципы UX (из IDEA):**
- **Ультра-минимализм и скорость.** Приложение должно запускаться мгновенно и не вызывать напряжения. Никакого визуального шума.
- **Тактильность.** Ключевые действия (перенос карточки в «Сделано», успешная выгрузка) подкрепляются мягкой вибрацией через Web Vibration API.
- **Мягкие анимации.** Используем Framer Motion с пружинами (`type: 'spring'`), а не резкими переходами. См. [src/components/StickyNote.jsx](src/components/StickyNote.jsx).
- **Язык интерфейса — русский.** Весь пользовательский текст на русском.
- **Спокойный тон.** Без давления и навязчивости — приложение предлагает, а не приказывает.

## 6. Архитектура состояния

Состояние живёт в Zustand-сторах (`store/`). Каждый модуль получает свой срез/стор.

**Текущий стор: `useCardsStore`** ([src/store/useCardsStore.js](src/store/useCardsStore.js)).

Модель карточки (создаётся в `createCard`):
```js
{
  id,         // crypto.randomUUID()
  text,       // одна мысль (см. принцип атомарности)
  color,      // { bg, shadow } из STICKY_COLORS
  rotation,   // лёгкий наклон стикера
  x, y,       // позиция на холсте
  createdAt,  // timestamp
}
```

Действия стора: `addCard`, `removeCard` (с отложенным undo), `undoDelete`, `dismissUndo`, `moveCard`, `setLastAddedId`.

**Как расширять состояние под новые модули:**
- Поля карточки для фильтрации/канбана (метки «Хочу/Должен», колонка канбана, статус) добавляются в модель карточки и фабрику `createCard`.
- Энергетические данные Power Management — отдельный стор (напр. `useEnergyStore`), чтобы не смешивать домены.
- Действия-мутации держим в сторе; компоненты только вызывают их.

## 7. PWA-требования

Формат PWA — обязательная часть продукта (см. IDEA, раздел 3). При реализации соответствующих фаз держи в голове:

- **Offline-first.** Выгрузка мысли должна работать мгновенно даже без сети (Service Worker + IndexedDB/Workbox). Синхронизация — фоновая, незаметная.
- **Персистентность.** Данные карточек должны переживать перезагрузку (локальное хранилище, затем облачная синхронизация).
- **Web Vibration API.** Тактильный отклик на ключевые действия.
- **Умные push-уведомления.** Контекстные мягкие триггеры (утром — выгрузка, при застое — пересмотр «узкого горлышка»), а не жёсткие напоминания по времени.
- **Мгновенный запуск.** Минимальный вес, быстрый старт с домашнего экрана.

## 8. Продуктовые инварианты (НЕ нарушать)

Это жёсткие правила из философии продукта. Реализация не должна их обходить:

- **Атомарность: «одна карточка — одна мысль».** Интерфейс и модель данных удерживают одну мысль на карточку.
- **WIP-лимит: «одно дело в единицу времени».** В колонке «В работе» канбана технически нельзя держать более одной карточки.
- **Pull-система, а не push.** Пользователь сам вытягивает следующую задачу в работу — приложение не навязывает порядок по календарю.
- **Предохранитель воли.** Если пользователь делает слишком много энергозатратных действий подряд, приложение предупреждает о риске срыва и предлагает восполнить энергию.
- **«Сначала осознание и оценка, потом действие».** Перед крупным проектом — калькулятор «Результат/Затраты».
- **Удаление без чувства вины.** Пустой «пожиратель времени» можно удалить в один клик; удаление всегда отменяемо (паттерн undo).
