# Уведомления KaizenFlow

По умолчанию работают **локально, без сервера** — через Service Worker и `showNotification`.
Подходит для iOS PWA на Home Screen и Android.

## iOS (без сервера)

1. Откройте сайт в **Safari**
2. «Поделиться» → **На экран „Домой“**
3. Запустите с Home Screen
4. Настройки → включите нужные типы → **Разрешить уведомления**

### Когда приходят локальные уведомления

| Тип | Когда срабатывает |
|-----|-------------------|
| Утро | При открытии приложения после 8:00, если сегодня ещё не выгружали |
| Затор | При открытии, если есть застрявшие дела (раз в день) |
| Слоны | 1-е число при открытии (раз в месяц) + badge в приложении |
| Неактивность | При возврате после ≥3 дней без визита |

Проверка повторяется каждые 30 минут, пока приложение открыто.

### Ограничение iOS

Пока приложение **полностью закрыто**, iOS не даёт PWA будить себя без сервера.
Локальные уведомления = **при открытии или возврате в приложение**.

---

## Android / Desktop

Тот же локальный режим. На Android в браузере (не PWA) уведомления тоже работают.

---

## Опционально: фоновый push через сервер

Если нужны уведомления **когда приложение закрыто** — Cloudflare Worker (см. `workers/push-api/`).

```bash
npm run push:generate-keys
```

`.env`:

```
VITE_VAPID_PUBLIC_KEY=...
VITE_PUSH_API_URL=https://your-worker.workers.dev
```

Деплой воркера — в `workers/push-api/README.md` (если добавите) или прежние шаги wrangler.

Без этих переменных приложение использует только локальный режим.

---

## Локальная разработка

```bash
npm run dev
```

Service Worker включён в dev-режиме. На реальном iPhone тестируйте через HTTPS-туннель
(например ngrok) или production-сборку — Safari требует secure context.

```bash
npm run build
npm run preview
```
