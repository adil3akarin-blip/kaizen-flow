# KaizenFlow — Workflow v2: таймеры, привычки, удаление «Энергии»

**Дата:** 2026-06-13
**Статус:** утверждён к исполнению
**Источник видения:** [context/IDEA.md](../../../context/IDEA.md) (раздел Power Management пересматривается этой спекой)
**Дизайн-система:** Hermes (светлая, оранжевый акцент + glassmorphism, `.hm-*` / glass-токены в `src/index.css`)

---

## Зачем это

Диагноз текущей концепции:

1. **Вкладка «Поток» дублирует «Канбан».** Конвейер данных один: `Выгрузка → Разбор → Очередь → В работе → Сделано`. «Поток» — это вид «одна карточка в фокусе», «Канбан» — вся доска. Две вкладки на один датасет; «Поток» не владеет ничем эксклюзивно.
2. **«Энергия» / Power Management непонятна и неизмерима.** Построена на self-report ползунках (перфекционизм↔пофигизм и т.п.) и «предохранителе воли». Тяжело заполнять честно, непонятно, что делать с ответом. Приложение не измеряет ничего объективного — только статусы карточек.

Решение: **заменить абстрактный Power Management на конкретные измеримые данные** — таймеры на задачах и трекер привычек, — и за счёт этого избавить «Поток» от дублирования, переосмыслив его в кокпит дня «Сегодня».

Принятые решения (подтверждены пользователем):
- «Поток» → **«Сегодня»** (таймер активной задачи + привычки дня).
- «Энергия» → **полное удаление**, мягкие подсказки темпа строятся на фактических данных таймера.
- Таймер → **секундомер + Помодоро**.
- Привычки → **гибкое расписание** (ежедневно / N раз в неделю / конкретные дни).
- Статистика/привычки сведены в общий хаб **«Прогресс»** (а не отдельной 5-й вкладкой).

## Информационная архитектура

**Нижний бар (mobile) — 4 вкладки + центральный FAB «Выгрузить»:**

```
Сегодня   Канбан   [ + ]   Разбор   Прогресс
```

| Вкладка | Содержание |
|---|---|
| **Сегодня** | Активная задача (WIP) с таймером + привычки на сегодня + итог дня. Бывший «Поток». |
| **Канбан** | Доска планирования. По сути без изменений (минус энергочипы). |
| **Разбор** | Фильтрация входящих. Минус энергошаг. |
| **Прогресс** | Сегментный переключатель `Привычки | Время`. Управление привычками, стрики, графы времени. Заменяет Energy Hub. |

- **Настройки** переезжают из нижнего бара (пункт «Ещё») в **шестерёнку хедера** (`TabPageHeader`) и остаются в desktop `Sidebar`. Освободившийся слот занимает «Прогресс».
- `TABS` в `useAppStore` обновляются: `flow → today`, добавляется `progress`; `settings` остаётся (доступ через шестерёнку), `review`/`kanban` без изменений.
- Desktop `Sidebar` синхронизируется с тем же набором.

## Экран «Сегодня»

Состоит из трёх зон (вертикально на mobile, две колонки на desktop как сейчас):

### Зона 1 — Фокус (герой)
- **Если есть WIP-карточка:**
  - текст карточки;
  - **живой таймер** mm:ss крупно; кнопки Старт / Пауза / Стоп;
  - сегмент режима **Секундомер | Помодоро**;
  - в Помодоро: текущая фаза (Фокус / Перерыв) с обратным отсчётом + точки завершённых помидоров за сессию;
  - подпись «Сегодня на задаче: 1ч 20м» (сумма сессий карточки за текущий день);
  - кнопки **Готово** (complete) и **Отпустить** (release) — переиспользуют существующую логику `completeWip` / `releaseWip`.
- **Если WIP пуст:** dashed-карточка «Вытяни дело из очереди» + мини-очередь для вытягивания (перенос текущей логики `WipSlot` + `PullQueue`).

### Зона 2 — Привычки сегодня
- Чек-лист привычек, у которых сегодня «положенный» день и они ещё не отмечены (+ отмеченные показываются зачёркнутыми/собранными).
- Тап = переключение отметки за сегодня; рядом стрик (🔥 N).
- Заголовок-счётчик «3 из 5 сделано».
- Пустой/нет привычек → ссылка «Добавить привычку» → ведёт в «Прогресс → Привычки».

### Зона 3 — Итог дня (замена энергии данными)
- Строка «Фокус сегодня: 1ч 20м · 3 помидора» из данных таймера.
- Мягкий nudge по порогу непрерывного фокуса (например, ≥90 мин подряд без паузы) → «Много фокуса подряд — сделай паузу». Никаких ползунков и self-report. Порог — константа в `timerUtils`.

## Таймер — модель и поведение

**Инвариант:** один активный таймер за раз (совпадает с WIP=1). Таймер работает над фокус-карточкой; запуск требует, чтобы карточка была в WIP.

### Стор `store/useTimerStore.js`
```
activeTimer: {
  cardId,
  mode: 'stopwatch' | 'pomodoro',
  phase: 'focus' | 'break' | null,   // null для секундомера
  startedAt,                          // ts запуска текущего отрезка
  accumulatedMs,                      // накоплено до текущего отрезка (после пауз)
  pomodorosCompleted                  // за текущую сессию
} | null

sessions: [{
  id, cardId, mode,
  startedAt, endedAt, durationMs,
  pomodorosCompleted
}]
```

Действия: `startTimer(cardId, mode)`, `pauseTimer()`, `resumeTimer()`, `stopTimer()` (финализирует сессию), `switchMode(mode)`, `tickPomodoro()` (переход фаз).

### Поведение
- **Тиканье:** в стор пишется `startedAt`; экран считает прошедшее от `startedAt + accumulatedMs`. Один `setInterval` в компоненте `FocusTimer`. На паузе `accumulatedMs += now - startedAt`, `startedAt = null`.
- **Перезагрузка при работающем таймере:** `activeTimer` персистится; время восстанавливается из `startedAt` (ничего не теряется).
- **Завершение/Отпускание карточки при идущем таймере:** сессия финализируется (`stopTimer`) до смены статуса карточки.
- **Помодоро:** конечный автомат 25 мин фокус / 5 мин перерыв; авто-переход фаз + `hapticTap()` + опц. push-уведомление; счёт завершённых помидоров. Длительности фокуса/перерыва настраиваются в Настройках (дефолт 25/5).
- **Производное `totalTimeMs` карточки** = сумма `durationMs` её сессий. Показывается в `CardEditSheet` (там же список сессий = история таймера по задаче) и опц. чипом в Канбане на колонке «Сделано».

### Утилиты `lib/timerUtils.js`
- `formatDuration(ms)`, `formatClock(ms)`.
- `sumSessionsByDay(sessions, range)`, `sumSessionsByCard(sessions)`, `sumSessionsByTag(sessions, cards)`.
- Автомат Помодоро (длительности фаз, переход), порог nudge паузы.

### Персистентность
- Ключ `kaizenflow-timer` через существующий паттерн `createDebouncedPersist` / `persistStorage`.
- Сессии накапливаются; для MVP без агрегации/обрезки (объёмы малы). Возможная агрегация — post-MVP.

## Привычки — модель и поведение

### Стор `store/useHabitsStore.js`
```
habits: [{
  id, title, icon, color,
  schedule: {
    type: 'daily' | 'weekly' | 'weekdays',
    timesPerWeek?,        // для 'weekly'
    weekdays?: [0..6]     // для 'weekdays', 0 = воскресенье (локально)
  },
  createdAt, archived
}]

log: { [habitId]: string[] }   // массив локальных дат 'YYYY-MM-DD' отметок
```

Действия: `addHabit(data)`, `updateHabit(id, patch)`, `archiveHabit(id)`, `toggleHabitDone(id, dateKey)`.

### Утилиты `lib/habitUtils.js`
- `localDateKey(date)` → 'YYYY-MM-DD' по локальной зоне.
- `isHabitDueOn(habit, date)` — должна ли привычка сегодня (по расписанию).
- `computeStreak(habit, log)` — текущая серия; считает только «положенные» дни (пропуск непоставленного дня обрывает стрик; неположенные дни не обрывают).
- `weeklyCompletionRate(habit, log, range)` — для хитмэпа/процентов.

### Поведение
- В «Сегодня» показываются привычки с `isHabitDueOn(habit, today) === true`.
- Полное управление (создать/редактировать/расписание/архив) и история — в «Прогресс → Привычки».
- Граница дня — по локальной дате (`localDateKey`); отметка привязана к календарному дню, без проблем при открытии приложения после полуночи.

### Персистентность
- Ключ `kaizenflow-habits` через существующий паттерн persist.

## «Прогресс» (замена Energy Hub)

Вкладка с сегментным переключателем `Привычки | Время` (компонент `progress/ProgressTab.jsx`).

### Сегмент «Привычки» (`HabitsView`)
- Список привычек: иконка/цвет, название, текущий стрик, расписание.
- Недельный календарь-хитмэп выполнения (последние N недель).
- Кнопка «Добавить привычку» → `HabitEditor` (название, иконка, цвет, расписание).
- Редактирование/архив существующей привычки.

### Сегмент «Время» (`TimeStatsView`)
- Столбчатый граф фокус-времени по дням (7 / 30 дней) — собственный лёгкий SVG-компонент `MiniBarChart`, **без внешней chart-библиотеки** (экономия бандла).
- Разбивка времени по тегам/колонкам (если есть теги) — простой список с долями.
- Тренд завершённых помидоров.
- Список последних сессий + суммарные показатели (всего за неделю/месяц).

## Edge cases

- **Перезагрузка с работающим таймером** → восстановление из `startedAt`, время не теряется.
- **Готово/Отпустить при идущем таймере** → сессия финализируется до смены статуса.
- **Несколько вкладок браузера** → таймер last-write-wins (как и карточки сейчас); для MVP допустимо, не усложняем.
- **Переход через полночь** → отметки привычек и агрегаты времени по локальной дате; nudge паузы считает непрерывный фокус в рамках сессии, не суток.
- **Удаление карточки с сессиями** → сессии остаются в истории времени (для статистики), но `CardEditSheet` недоступен; в `TimeStatsView` помечаются как «без задачи». (Альтернатива — удалять сессии вместе с карточкой; решить в плане, дефолт — сохранять для статистики.)
- **Помодоро в фоне/свёрнутом приложении** → переход фаз вычисляется от `startedAt` при возврате, не зависит от тиканья на переднем плане.
- **Перевод часов** → стрики/агрегаты на локальных датах; guard от отрицательной дельты в таймере (`Math.max(0, …)`).
- **Старые данные с `energyCost`/`resultEffort`** → санитайзер дропает поля, ошибок нет.

## Критерии готовности

- Вкладки: `Сегодня · Канбан · Разбор · Прогресс` + FAB; настройки через шестерёнку; «Поток» как отдельный дубль исчез.
- На «Сегодня» активная задача имеет рабочий таймер (секундомер и Помодоро), время переживает перезагрузку.
- Время по задаче видно в `CardEditSheet` (история сессий) и агрегируется в «Прогресс → Время» (граф по дням).
- Привычки с гибким расписанием: отметка в «Сегодня», стрики и хитмэп в «Прогресс → Привычки».
- Энергия/предохранитель воли/экран паузы/ползунки полностью удалены; `rg 'energy|Energy|willpower|resultEffort|Pause' src/` даёт 0 совпадений (кроме, возможно, нейтральных слов).
- `npm run lint && npm run build` зелёные.
