# Генерализация Канбана: доски + колонки с ролями (дизайн)

Дата: 2026-06-14
Статус: утверждён к реализации (полная генерализация, «всё сразу»)

## Цель

Дать пользователю: создавать/редактировать/удалять колонки и иметь несколько
досок с переключением. Единая модель: «Поток» — это одна из досок (system),
колонки несут роли, дающие потоковую семантику.

## Решения (утверждены)

- Полная генерализация: «Поток» — доска `system:true` с ролевыми колонками.
- «Поток» сохраняет идентичность: WIP=1, кормит «Сегодня»/«Разбор»/стрик.
- Общий (глобальный) WIP на все доски — принцип «узкого горлышка».
- Кастомные доски — прямой ввод карточек в колонку (без «Выгрузка→Разбор»).
- Удаление колонки → её карточки переезжают в первую колонку доски.
- done-колонка на любой доске считается «сделано» (стрик/достижения).

## Модель данных

### `useBoardsStore` (новый, персист `kaizenflow-boards`)

```
boards: [
  { id:'flow', name:'Поток', system:true, columns:[
      {id:'queue',    label:'Очередь',  role:'queue'},
      {id:'progress', label:'В работе', role:'wip', wipLimit:1},
      {id:'done',     label:'Сделано',  role:'done'},
      {id:'next_week',label:'След. неделя', role:'queue', dayHidden:true} ]},
  …пользовательские доски с колонками role:'plain' по умолчанию
]
activeBoardId: 'flow'
```

Роль колонки `role`: `queue | wip | done | plain`.
Действия: `addBoard`, `renameBoard`, `deleteBoard`, `setActiveBoard`,
`addColumn`, `renameColumn`, `deleteColumn`, `reorderColumns`, `setColumnRole`.
Гард: `flow` нельзя удалить; нельзя удалить последнюю колонку доски.

### Карточки (`useCardsStore`)

- Новое поле `boardId` (миграция: карточки со статусом kanban → `'flow'`;
  отсутствие boardId трактуется как `'flow'`).
- `kanbanColumn` = id колонки внутри доски карточки.
- `status` — денормализован, выводится из роли целевой колонки при каждом
  перемещении (`roleToStatus`: queue→filtered, wip→wip, done→done, plain→board).
  Читатели (`cardSelectors`, стрик, «Сегодня», «Разбор», достижения)
  продолжают читать `card.status` — меняются только действия перемещения.
- `'raw'` — прежний pre-board статус (дамп/разбор, интейк «Потока»), без доски.

### Порядок (`columnOrder`)

Обобщается в per-board: `{ [boardId]: { [columnId]: [cardId…] } }`.
Миграция: текущий плоский порядок → `{ flow: <старый порядок> }`.
`kanbanOrderUtils` обобщается: операции принимают список колонок доски и
работают со срезом порядка этой доски.

## Семантика ролей (единый поток)

- `wip` глобально один: перемещение в любую `wip`-колонку при занятом WIP →
  диалог-гейт (`WipGateDialog`). `selectWipCard` работает по статусу — глобально.
- `done` где угодно → статус `done` → стрик/«Музей побед»/год.
- `queue` → статус `filtered` → pull-очередь «Сегодня». Кастомные доски по
  умолчанию `plain`, поэтому в поток не текут, пока колонке не задана роль.
- `plain` → статус `board` (нейтральный) — карточка видна только на своей доске.

## UI

- **Переключатель досок** сверху Канбана: пилюли `[Поток] [Проект X] … [+ Доска]`.
  Меню доски (переименовать/удалить) для не-system.
- **Колонка**: заголовок с счётчиком + меню `⋯` (переименовать · роль · удалить).
  В конце ряда — призрак `+ колонка`. В подвале колонки — `+ карточка`.
- **Рендерер**: обобщённый `KanbanBoard` берёт колонки из `board.columns` и срез
  порядка доски. WIP-гейт срабатывает, когда роль целевой колонки `wip`.
  День/Неделя/Музей — chrome доски «Поток» (next_week через `dayHidden`); Музей
  (`YearBoard`) остаётся отдельной кнопкой.
- Кастомные доски: без День/Неделя, просто их колонки.

## Порядок реализации (послойно, с проверкой)

1. `useBoardsStore` + сид «Поток» + миграция.
2. Обобщить `kanbanOrderUtils` (приём списка колонок + per-board срез) и
   `kanbanUtils` (roleToStatus / columnRole helpers).
3. Карточки: `boardId`, миграция персиста (`{cards, columnOrder, ...}` →
   per-board order), обобщить move-действия (status из роли, общий WIP).
4. Обобщить `KanbanBoard` под `board` + переключатель досок в `KanbanTab`.
5. CRUD колонок (меню/шиты) + добавление карточек на доску.
6. CRUD досок (создать/переименовать/удалить).
7. Роли колонок (пикер) + проверка единого потока (done→стрик, общий WIP).
8. Проверка: flow-доска работает идентично; preview desktop+mobile; lint; тесты.

## Граничные случаи / риски

- Миграция старых данных без `boardId`/плоского `columnOrder` — трактуем как flow.
- Удаление колонки с картами → в первую колонку доски (порядок сохраняем).
- Нельзя осиротить карты: при удалении доски — удаляем её карты (с подтверждением).
- Глобальный WIP: один `wip` на всё приложение; гейт переиспользуем.
- Тесты: юнит на `kanbanOrderUtils` (обобщённые) + `roleToStatus`/миграцию.
