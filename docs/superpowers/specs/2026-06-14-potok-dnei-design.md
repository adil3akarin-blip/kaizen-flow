# «Поток дней» — дизайн (Tier 1 эволюции KaizenFlow)

Дата: 2026-06-14
Статус: утверждён к реализации

## Контекст и цель

Эволюция KaizenFlow на основе исследования геймификации RPGreal
(`context/kaizen/RPG-Life Tracker.html`). Цель — повысить Retention,
сохранив философию Кайдзен (спокойный поток, одно дело в единицу времени,
низкая когнитивная нагрузка, никаких авралов; урок 12).

Из всех механик RPGreal в Tier 1 берём три, которые двигают Retention и
**не ломают спокойствие**:

1. **Поток дней** — глобальный мягкий стрик (адаптация 🔥 Streaks / Loss
   Aversion, но без давления «потеряешь!»).
2. **Момент завершения** — тёплая микро-обратная связь при закрытии дела
   (Progress Principle — «малые победы»).
3. **Дневной прогресс** — «дела потока» сегодня (Goal Gradient, XP без
   произвольных очков).

Намеренно **не** берём: рулетку/лутбоксы (Skinner), лидерборды/группы,
давление «потеряешь стрик». Ранги по сферам — отдельный Tier 2.

## Ключевые решения (утверждены)

- **Активный день** = любое действие: закрыта ≥1 карточка, ИЛИ была
  фокус-сессия, ИЛИ отмечена привычка. Низкий порог — поощряем «просто прийти».
- **Мягкая заморозка**: 1 прощённый пропуск в скользящие 7 дней. Поток не
  рвётся, заморозка показывается явно (видимое прощение, не магия).
- **Дневная цель** = 3 «дела потока» (атомарные действия — в духе
  «равномерности нагрузки»). 1 действие держит поток, 3 = «день в потоке».
  Превышение цели не наказывается и не подгоняет.

## Архитектура

Всё **выводится из существующих данных** — новый персист-стор не нужен,
нет риска рассинхрона. Источники активности:

| Источник | Где | Ключ дня |
| --- | --- | --- |
| Закрытые карточки | `useCardsStore.cards`, `status==='done'` | `localDateKey(card.completedAt ?? card.createdAt)` |
| Фокус-сессии | `useTimerStore.sessions[]` | `localDateKey(session.endedAt)` |
| Привычки | `useHabitsStore.log[habitId][]` | значения уже `'YYYY-MM-DD'` |

`localDateKey` и `useTodayKey` (корректный переход через полночь) уже
существуют в `src/lib/timerUtils.js` и `src/lib/useTodayKey.js`.

### Новые файлы

**`src/lib/streakUtils.js`** — чистые функции (без React, без сторов):

- `collectActiveDays(cards, sessions, habitLog) -> Set<string>`
  Объединение дней-ключей из трёх источников.
- `computeFlowStreak(activeDays, now = Date.now()) -> {`
  `  streak, isTodayActive, bestStreak, weekDays, frozenToday }`
  - Идёт назад от сегодня. «Сегодня ещё не активно» **не** рвёт поток —
    отсчёт начинается с последнего активного/прошедшего дня (как
    `computeStreak` для привычек).
  - **Заморозка**: наткнувшись на неактивный день, «перешагивает» его, если
    в последних 7 днях обхода заморозка ещё не тратилась
    (`lastFreezeKey == null || daysBetween(curr, lastFreezeKey) >= 7`).
    Иначе поток заканчивается. Перешагнутый день помечается замороженным.
  - `bestStreak` — максимум за всю историю тем же правилом.
  - `weekDays` — массив из 7 элементов (Пн…Вс текущей недели) со статусом
    `'done' | 'frozen' | 'today' | 'empty' | 'future'` для недели в hero.
  - `frozenToday` — была ли заморозка применена в текущем окне (для подсказки).
- `computeDayFlowCount(cards, sessions, habitLog, dayKey) -> number`
  Сколько «дел потока» закрыто за конкретный день (для дневного прогресса).
  Цель — константа `DAY_FLOW_TARGET = 3`.

**`src/lib/useFlowStreak.js`** — хук. Подписывается на `cards`, `sessions`,
`log` и `useTodayKey()`; мемоизирует `computeFlowStreak` +
`computeDayFlowCount`. Возвращает данные для hero.

**`src/components/today/FlowStreakHero.jsx`** — hero-карточка:
пламя + число стрика + «рекорд — N», ряд недели (Пн…Вс с заморозкой),
дневной прогресс «N из 3». Стиль — Hermes (`hm-glass`, оранжевый акцент
`#f97316`, токены `text-ink/-muted/-faint`). Пустое состояние (стрик 0):
«Закрой первое дело — начнётся твой поток».

### Изменения существующего

- **`src/components/tabs/TodayTab.jsx`** — `<FlowStreakHero />` первым
  блоком, над `<DailySummary />`.
- **Момент завершения** — в точке закрытия WIP-дела (вызов `completeWip`,
  см. `WipSlot.jsx` / `StructuredCard.jsx`): тёплый тост через
  `useToastStore` + `hapticTap()` (оба уже есть). Спокойный, без конфетти.
  Текст в духе: «Готово. Поток держится — N дней подряд».

## Граничные случаи

- Нет истории → `streak = 0`, hero в режиме онбординга.
- Только сегодняшняя активность → `streak = 1`, `isTodayActive = true`.
- Заморозка отображается снежинкой + tooltip «заморозка спасла поток».
- Дубли дней между источниками схлопываются через `Set`.
- Будущие дни недели (после сегодня) — статус `'future'`, нейтральный вид.

## Тестирование

В проекте нет тест-раннера. Добавляем **vitest** (узко, под `streakUtils`):

- devDependency `vitest`; скрипты `"test": "vitest"`,
  `"test:run": "vitest run"`.
- `src/lib/streakUtils.test.js` покрывает самую хрупкую логику:
  - пустая история → 0;
  - непрерывная цепочка → корректная длина;
  - один пропуск в пределах 7 дней → заморозка спасает, поток продолжается;
  - два пропуска в окне 7 дней → поток рвётся;
  - «сегодня ещё не активно» не обнуляет вчерашний поток;
  - `bestStreak` ≥ текущего;
  - `computeDayFlowCount` считает три источника без двойного учёта.

Компоненты/вёрстка проверяются на dev-сервере через preview-инструменты.
